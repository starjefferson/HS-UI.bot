  1. WHAT THIS BOT DOES (PLAIN ENGLISH)
================================================================================

  This is an automated Forex trading bot that:

  - Watches 7 currency pairs at the same time:
    EURUSD, GBPUSD, USDJPY, USDCHF, USDCAD, AUDUSD, NZDUSD

  - Scans candle data across 4 timeframes (Weekly, Daily, 4-Hour, 1-Hour)

  - Looks for ONE specific chart pattern: "Head and Shoulders" (H&S) and its
    mirror image "Inverted Head and Shoulders"

  - Only trades when MULTIPLE conditions line up:
    ✓ The pattern must be confirmed by multi-timeframe analysis
    ✓ The overall market trend must agree with the pattern direction
    ✓ The neckline must actually BREAK before a trade is entered
    ✓ The Risk:Reward must be between 2.5 and 3.0
    ✓ It must be within trading hours (8am–9pm GMT+1)
    ✓ The weekly trade limit must not be exceeded

  - Calculates the correct lot size automatically based on your account balance
    and 5% risk per trade

  - Places trades directly via Deriv's WebSocket API — no MetaTrader 5, no
    desktop trading terminal required

================================================================================
  2. HOW THE BOT MAKES TRADING DECISIONS
================================================================================

  The bot follows this exact sequence for every pair, once per hour
  (approximately 5 seconds after each new hour candle opens):

  STEP 1 — TRADING HOURS CHECK
  ─────────────────────────────
  The bot first checks if the current time is between 08:00 and 21:00 GMT+1.
  Outside this window, the bot does nothing. This is because Asian session
  tends to have low volume and fake breakouts, and late-night entries have
  worse execution. If you are in Nigeria or West Africa, GMT+1 is your local
  time (WAT). So the bot trades 8am to 9pm your time.

  STEP 2 — TOP-DOWN TREND ALIGNMENT (3-of-4 Filter)
  ───────────────────────────────────────────────────
  The bot checks all 4 timeframes (Weekly, Daily, 4H, 1H) and asks:
  "Is price above or below the 20-period Simple Moving Average?"

  - Price ABOVE the 20 SMA = Bullish (buy bias)
  - Price BELOW the 20 SMA = Bearish (sell bias)

  For a trade to be considered:
  - At least 3 out of 4 timeframes must agree

  Example: If W1=buy, D1=buy, H4=buy, H1=sell → 3 of 4 say buy → BUY BIAS
  Example: If W1=sell, D1=buy, H4=buy, H1=buy → 3 of 4 say buy → BUY BIAS
  Example: If W1=buy, D1=sell, H4=buy, H1=sell → only 2 agree → NO TRADE

  STEP 3 — HEAD & SHOULDERS PATTERN DETECTION
  ─────────────────────────────────────────────
  What is a Head and Shoulders pattern?

  It looks like this on a chart:

      Left    HEAD    Right
    Shoulder  (top)  Shoulder
       /\      /\      /\
      /  \    /  \    /  \
     /    \  /    \  /    \
    /      \/      \/      \
    ─────────────────────────  ← NECKLINE
    (price should break below here)

  This is a BEARISH reversal pattern. It means the market tried to go up 3
  times, with the middle attempt (the "head") going the highest. After the
  right shoulder forms, the market runs out of buyers and is about to fall.

  The INVERTED version (Inverse H&S) is the mirror image and signals a BULLISH
  reversal — price tried to go down 3 times and is about to rise.

  The bot scans 250 candles of history looking for these formations.

  STEP 4 — DIRECTION CONFIRMATION
  ─────────────────────────────────
  The pattern direction must match the trend bias from Step 2.
  - H&S (sell pattern) is ONLY valid if the bias is also "sell"
  - Inverted H&S (buy pattern) is ONLY valid if the bias is also "buy"

  If they don't match, the signal is rejected with "bias_mismatch".

  STEP 5 — NECKLINE BREAKOUT CONFIRMATION
  ─────────────────────────────────────────
  The bot does NOT enter the moment the pattern is spotted.
  It WAITS for the neckline to actually break.

  For a SELL:
  - The previous H1 candle must have closed AT or ABOVE the neckline
  - The current candle must close BELOW the neckline by at least 2 pips
  → This confirms sellers are in control

  For a BUY:
  - The previous H1 candle must have closed AT or BELOW the neckline
  - The current candle must close ABOVE the neckline by at least 2 pips
  → This confirms buyers are in control

  Without this breakout, the bot just logs "Monitoring for Neckline Breakout"
  and waits for the next scan cycle.

  STEP 6 — RISK:REWARD CHECK
  ────────────────────────────
  The bot calculates the distance from entry to Stop Loss (the risk) and
  from entry to Take Profit (the reward).

  RR = (distance to TP) / (distance to SL)

  Only trades with RR between 2.5 and 3.0 are executed.
  - RR below 2.5 = not profitable enough for the risk taken
  - RR above 3.0 = the SL is probably too tight and the pattern may be wrong

  STEP 7 — TRADE EXECUTION
  ─────────────────────────
  If all checks pass, the bot sends the trade order directly to Deriv via
  the WebSocket API (wss://ws.derivws.com). No intermediate file or MT5
  handshake is involved.

  STEP 8 — LOT SIZE CALCULATION
  ──────────────────────────────
  The bot calculates lot size using:

  Risk Amount = Account Balance × 5%
  Stop Loss in pips = |Entry Price − SL Price| ÷ pip size
  Lot Size = Risk Amount ÷ (SL pips × pip value)

  This means if your balance grows, lot sizes grow. If your balance shrinks,
  lot sizes shrink. Your account risk is always approximately 5% per trade.

  3. SYSTEM ARCHITECTURE
================================================================================

  The bot consists of TWO separate processes that run together:

  ┌─────────────────────────────────────────────────────────────────┐
  │  PART 1: BOT ENGINE (index.js)                                 │
  │  Runs on: Your computer or VPS (Node.js process)               │
  │  Role: Brain — fetches candles from Deriv via WebSocket,        │
  │         detects H&S patterns, calculates RR, executes trades   │
  │         directly to your Deriv account                         │
  │                                                                 │
  │  Candle data is fetched ONCE PER HOUR, approximately 5 seconds │
  │  after the new H1 candle opens, to ensure a fully closed       │
  │  candle is used for entry confirmation. There is no reason to  │
  │  poll more frequently — the strategy requires a minimum 1-hour │
  │  candle close for pattern and neckline confirmation.           │
  └─────────────────────────────────────────────────────────────────┘
                              │
                              │ Live WebSocket
                              │ wss://ws.derivws.com
                              ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  DERIV PLATFORM (wss://ws.derivws.com)                         │
  │  Provides: Live candle data (all timeframes)                   │
  │  Receives: Contract / trade orders from the bot engine         │
  │  No MetaTrader 5. No Expert Advisors. No desktop terminal.     │
  └─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  PART 2: NEXT.JS DASHBOARD (app/)                              │
  │  Runs on: Browser at http://localhost:3000                     │
  │  Port: 3000 (can be exposed publicly on VPS)                   │
  │  Role: Eyes — shows balance, open trades, trade history        │
  └─────────────────────────────────────────────────────────────────┘

  IMPORTANT: No MetaTrader 5 installation is required. Everything
  runs entirely in Node.js and communicates with Deriv directly
  over WebSocket. Both processes (bot engine + dashboard) are
  managed by PM2 on your Linux/Windows VPS.


================================================================================
  4. FILE-BY-FILE EXPLANATION
================================================================================

  PROJECT ROOT FILES:
  ────────────────────

  index.js
    The main bot engine. This is the brain of the entire system.
    It connects to Deriv's WebSocket API (wss://ws.derivws.com) and runs
    a continuous hourly loop:
    - Once per hour (≈5 seconds after the new H1 candle opens): fetches
      candle data for all 7 pairs across all 4 timeframes
    - Runs top-down trend analysis (3-of-4 SMA filter)
    - Runs H&S pattern detection and neckline breakout checks
    - If a valid signal is found: places a contract directly on Deriv
      via the same WebSocket connection

  config.js
    All the settings for the bot in one place:
    - pairs: which currency pairs to watch
    - tradingHours: start and end hour (GMT+1)
    - maxTradesPerWeek: weekly safety limit
    - riskPercent: % of balance to risk per trade (set to 5%)
    - rrRatio: the minimum reward-to-risk ratio
    Change numbers here to adjust bot behaviour — do NOT edit index.js for this.

  .env.local
    Your private credentials. Not committed to Git. Contains:
    - DERIV_APP_ID: your Deriv application ID
    - DERIV_API_TOKEN: your Deriv account API token (treat like a password)

  history.json
    Internal log of all signals that have been executed. Used to prevent the
    same pattern from being traded more than once (via patternID matching).

  signals.json
    Temporary queue file. When a valid signal is detected, it is written here
    and immediately sent to Deriv. Cleared on every bot restart.

  pm2.ecosystem.config.cjs
    PM2 process manager configuration. Used on VPS to keep both the bot engine
    and dashboard alive 24/7 with automatic crash recovery.

  SRC/ FOLDER (bot engine modules):
  ───────────────────────────────────

  src/patternDetection/headShoulders.js
    Contains the structural pattern detection algorithm.
    - Uses a "sliding window" of radius 5 candles to confirm structural pivots
    - Can provisionally monitor a forming right shoulder after the first four pivots
    - Updates the provisional right-shoulder level and stop as that pivot extends
    - Calculates neckline levels and measured-move targets from the detected structure
    - Entry still requires a closed 1H candle to break the neckline by the configured buffer

  src/patternDetection/patternEngine.js
    Orchestrates the detection across timeframes.
    - Runs headShoulders.js on D1, H4, and H1 data
    - Requires H1 to have a pattern (most precise)
    - If D1 or H4 also have patterns, their direction must agree with H1
    - Validates that the TP is placed on the correct side of the neckline

  src/patternDetection/topDownAnalysis.js
    Standalone top-down trend check.
    - Checks all 4 timeframes against the 20-period SMA
    - Returns the dominant bias (buy/sell) and the score (e.g. 3/4)

  src/riskManagement/risk.js
    Weekly trade frequency control.
    - canTrade(): reads closedTrades.json, counts trades in the current week
    - Returns false if maxTradesPerWeek has been reached
    - Also enforces minDaysBetweenTrades cooldown (currently 0 = no cooldown)

  src/notificationService/emailNotifications.js
    Placeholder for email alerts. Currently just logs to the console.
    Future implementation: connect to an SMTP server or email API (e.g. Nodemailer,
    SendGrid) to get alerts on your phone when a trade is placed.

  APP/ FOLDER (Next.js dashboard):
  ──────────────────────────────────

  app/page.js
    The main page — just renders the Dashboard component.

  app/layout.js
    Sets the font, background, and page metadata.

  app/api/broker/route.js
    Next.js API routes for the dashboard to read data:
    - GET /api/broker?type=balance  → fetches live balance from Deriv API
    - GET /api/broker?type=open     → reads last open trade from closedTrades.json
    - GET /api/broker?type=trades   → counts total trades in closedTrades.json

  src/components/Dashboard.js
    The visual interface showing three cards: Account Balance, Open Trade, Total Trades.

  5. SETTING UP ON YOUR COMPUTER (FIRST TIME)
================================================================================

  REQUIREMENTS:
  - Node.js v18 or newer. Download from: https://nodejs.org
  - A Deriv account (Real or Demo). Sign up at: https://deriv.com
  - A Deriv API Token with Read, Trade, Payments, Admin scopes
  - A terminal (Command Prompt, PowerShell, or Windows Terminal)
  - NO MetaTrader 5 required. NO Expert Advisors. NO broker MT5 account.

  STEP 1 — Open a terminal in the project folder
  ──────────────────────────────────────────────
  Open PowerShell or Command Prompt.
  Type this command to go to the project folder:

    cd "C:\Users\DELL PC\Documents\HS-UI.bot"

  Press Enter.

  STEP 2 — Install Node.js dependencies
  ──────────────────────────────────────
  Run this command:

    npm install

  This downloads all the libraries the bot needs (ws, Next.js, etc.).
  It will take 1–2 minutes. You'll see a lot of text scrolling — that's normal.
  When it finishes, you'll see a line like "added 500 packages".

  STEP 3 — Verify the install worked
  ────────────────────────────────────
  Run this to check:

    node --version

  You should see something like: v20.11.0 (or higher)

    npm --version

  You should see something like: 10.x.x

  6. SETTING UP METATRADER 5 — STEP BY STEP (EXACT CLICKS)
================================================================================

  This section gives you the EXACT sequence of clicks and menu items.

  ════════════════════════════════════════════════════════════════════════════
  PART A: ALLOW THE EA TO MAKE INTERNET REQUESTS (CRITICAL — DO THIS FIRST)
  ════════════════════════════════════════════════════════════════════════════

  Without this step, the EA cannot communicate with the Node.js server
  and you will see "WebRequest Error: 4060" in the MT5 Journal tab.

  Step A1: Open MetaTrader 5

  Step A2: Click "Tools" in the top menu bar
            (the menu bar at the very top: File | View | Insert | Charts |
             Tools | Window | Help)

  Step A3: Click "Options" (near the bottom of the Tools dropdown)
            → A settings window will open

  Step A4: Click the "Expert Advisors" tab
            (you'll see tabs: Charts | Trade | Expert Advisors | Notifications |
             Email | FTP | Community | Signals)

  Step A5: Make sure this checkbox is TICKED:
            ✅ "Allow WebRequest for listed URL:"

  Step A6: In the text box directly below that checkbox, type:
            http://127.0.0.1:3001
            Then click the [+] (Add) button to the right of the text box.
            The URL should now appear in the list below.

  Step A7: Click [OK] to save and close the Options window.

  → You have now given the EA permission to talk to the local Node.js server.

  ════════════════════════════════════════════════════════════════════════════
  PART B: COMPILE THE EXPERT ADVISOR FILE
  ════════════════════════════════════════════════════════════════════════════

  Step B1: Click "Tools" → "MetaQuotes Language Editor"
            (or press F4 on your keyboard)
            → A new window called "MetaEditor" will open

  Step B2: In MetaEditor, click "File" → "Open"

  Step B3: Navigate to your project folder:
            C:\Users\DELL PC\Documents\HS-UI.bot\

  Step B4: Select "MT5_TradeExecutor.mq5" and click Open

  Step B5: Press F7 (or click "Compile" in the toolbar)
            → You should see in the bottom panel:
              "0 errors, 0 warnings"
            → If you see errors, check that you did not accidentally edit the
              .mq5 file. Contact for support.

  Step B6: Close MetaEditor (you can keep it open if you like)

  ════════════════════════════════════════════════════════════════════════════
  PART C: ADD ALL 7 CURRENCY PAIRS TO MARKET WATCH
  ════════════════════════════════════════════════════════════════════════════

  The EA watches 7 pairs. They all need to be visible in MT5's Market Watch.

  Step C1: In the main MT5 window, press Ctrl+M to open Market Watch
            (or click View → Market Watch)

  Step C2: Right-click anywhere inside the Market Watch panel

  Step C3: Click "Show All" — this adds all available symbols

  Step C4: Or, to add individually: right-click → "Symbols"
            Search for each pair and double-click to add:
            → EURUSD, GBPUSD, USDJPY, USDCHF, USDCAD, AUDUSD, NZDUSD

  ════════════════════════════════════════════════════════════════════════════
  PART D: ATTACH THE EA TO A CHART
  ════════════════════════════════════════════════════════════════════════════

  The EA only needs to run on ONE chart. It will scan all 7 pairs internally.
  Use EURUSD H1 as the host chart (it's the most liquid and always has data).

  Step D1: In Market Watch, double-click "EURUSD" to open a chart

  Step D2: On the chart timeframe bar (M1 M5 M15 M30 H1 H4 D1 W1 MN),
            click "H1" to set it to the 1-Hour timeframe

  Step D3: In MetaEditor (or back in MT5), find the Navigator panel.
            Press Ctrl+N to open the Navigator if it's not visible.

  Step D4: In the Navigator, expand "Expert Advisors"
            → You should see "MT5_TradeExecutor" listed there

  Step D5: Double-click "MT5_TradeExecutor"
            → An "Expert Advisor Properties" window will open

  Step D6: In the "Common" tab, make sure these are checked:
            ✅ Allow Automated Trading
            ✅ Allow DLL Imports (if shown)

  Step D7: In the "Inputs" tab you can see and adjust:
            - ExecuteURL: http://127.0.0.1:3001/execute   (leave as-is)
            - CandlesURL: http://127.0.0.1:3001/candles   (leave as-is)
            - BarsToRequest: 250                           (leave as-is)

  Step D8: Click [OK]
            → The EA icon (a small smiley face) should now appear in the
              top-right corner of the EURUSD H1 chart
            → The face should be YELLOW (meaning automated trading is ON)
              If it's GREY, click the "AutoTrading" button in the MT5 toolbar

  ════════════════════════════════════════════════════════════════════════════
  PART E: ENABLE AUTOMATED TRADING (MASTER SWITCH)
  ════════════════════════════════════════════════════════════════════════════

  Step E1: Look at the MT5 toolbar at the top of the screen
            Find the button that says "AutoTrading"
            (it has a green play icon next to it)

  Step E2: If the button is greyed out or shows "AutoTrading" with a red icon,
            CLICK IT to enable automated trading.

  Step E3: The EA face on the chart should now turn YELLOW (not grey or red).

  → The bot is now active. It will start sending candle data to the server
    5 minutes after attaching (on the next 5-minute cycle).

  ════════════════════════════════════════════════════════════════════════════
  PART F: CHECK THE MT5 JOURNAL (VERIFY IT'S WORKING)
  ════════════════════════════════════════════════════════════════════════════

  Step F1: Look at the bottom of the MT5 window.
            You'll see tabs: Trade | History | Alerts | Mailbox | Journal | Experts

  Step F2: Click the "Experts" tab (NOT Journal — "Experts" shows EA logs)

  Step F3: After attaching the EA, you should see log messages like:
            "🚀 HS-Bot Bridge Active | Port 3001"       ← server started
            "📤 [EURUSD] Scan response: {"status":"scanning"}"
            "📤 [GBPUSD] Scan response: {"status":"outside_hours"}"

  Step F4: If you see:
            "⛔ WebRequest blocked. Go to: Tools → Options..."
            → Go back to Part A and make sure the URL was added correctly.

            "WebRequest Error: -1"
            → The Node.js server is not running. Start it first (Section 7).

  8. DEPLOYING TO A VPS (24/7 OPERATION)
================================================================================

  A VPS (Virtual Private Server) is a computer in the cloud that stays on
  24/7. You rent one monthly. This is how you keep the bot running even when
  your own computer is off.

  RECOMMENDED VPS SPEC:
  - 2 GB RAM minimum (4 GB recommended)
  - Ubuntu 22.04 LTS operating system
  - 20 GB SSD storage
  - Providers: Contabo, DigitalOcean, Vultr, AWS EC2

  NOTE FOR MT5:
  If you deploy to a Linux VPS, MT5 does NOT run natively on Linux.
  Options:
  a) Use a Windows VPS (more expensive, ~$10–20/month)
      → Install MT5 on the Windows VPS normally
      → Deploy the Node.js server on the same Windows VPS
  b) Use Wine on Linux (advanced — emulates Windows, runs MT5)
  c) Keep MT5 running on your local Windows PC
      → Change ExecuteURL and CandlesURL in the EA from http://127.0.0.1:3001
        to http://YOUR_VPS_IP:3001
      → Open port 3001 in your VPS firewall

  SIMPLEST SETUP: Windows VPS with both MT5 and Node.js on the same machine.

  STEP-BY-STEP VPS DEPLOYMENT:
  ──────────────────────────────

  STEP 1 — SSH into your VPS
    ssh root@YOUR_VPS_IP
    (Use PuTTY on Windows if you don't have an SSH client)

  STEP 2 — Install Node.js on the VPS
    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
    sudo apt-get install -y nodejs

  STEP 3 — Install PM2 globally
    npm install -g pm2

  STEP 4 — Upload your project to the VPS
    Option A (from your computer using SCP):
      scp -r "C:\Users\DELL PC\Documents\HS-UI.bot" root@YOUR_VPS_IP:/root/hs-bot

    Option B: Use GitHub
      git push to GitHub from your computer
      git clone https://github.com/YOUR_USERNAME/HS-UI.bot /root/hs-bot

  STEP 5 — Navigate to the project on the VPS
    cd /root/hs-bot

  STEP 6 — Install dependencies
    npm install

  STEP 7 — Build the Next.js dashboard
    npm run build
    (This takes 1–3 minutes. Run it only once, or after making UI changes)

  STEP 8 — Start both processes with PM2
    npm run start:prod
    (This is the same as: pm2 start pm2.ecosystem.config.cjs)

  STEP 9 — Verify both are running
    pm2 status

    You should see:
    ┌─────────────────────┬────────┬──────┬──────┬──────┐
    │ name                │ status │ cpu  │ mem  │ ...  │
    ├─────────────────────┼────────┼──────┼──────┼──────┤
    │ hs-bot-server       │ online │ 0%   │ 50mb │      │
    │ hs-dashboard        │ online │ 0%   │ 80mb │      │
    └─────────────────────┴────────┴──────┴──────┴──────┘

  STEP 10 — Set PM2 to restart on VPS reboot
    pm2 startup
    (Copy the command it outputs and run it — it will look something like:
     sudo env PATH=... pm2 startup systemd -u root --hp /root)
    pm2 save

  STEP 11 — Open firewall port for the dashboard (optional)
    ufw allow 3000
    (Port 3001 should NOT be exposed publicly — it's for MT5 only)

  STEP 12 — Access the dashboard in your browser
    http://YOUR_VPS_IP:3000

  USEFUL PM2 COMMANDS:
  ──────────────────────
    pm2 status           → see if both processes are running
    pm2 logs             → see live output from both processes
    pm2 logs hs-bot-server  → logs from the bot server only
    pm2 restart all      → restart both processes
    pm2 stop all         → stop both processes
    pm2 monit            → live CPU/memory monitor (press q to exit)
    pm2 delete all       → remove from PM2 (does not delete your files)

  9. CONFIGURATION REFERENCE

  ├─────────────────────────┼──────────────────────────────────────────────────┤

  11. WHAT TO DO WHEN SOMETHING GOES WRONG
================================================================================

  PROBLEM: "WebRequest Error: 4060" in MT5 Experts tab
  SOLUTION: Go to Tools → Options → Expert Advisors → Allow WebRequest →
            Add http://127.0.0.1:3001 → Click [+] → Click OK

  PROBLEM: MT5 EA face is grey (not yellow)
  SOLUTION: Click the "AutoTrading" button in the MT5 toolbar to enable it.
            Also check: Tools → Options → Expert Advisors → Allow Automated Trading

  PROBLEM: No log messages appearing at all after attaching EA
  SOLUTION: Check the "Experts" tab (not Journal) at the bottom of MT5.
            Make sure the Node.js server is running (you should see port 3001 active).

  PROBLEM: Server starts but immediately crashes with "MODULE NOT FOUND"
  SOLUTION: Run `npm install` again. A dependency is missing.

  PROBLEM: "Cannot find module './src/riskManagement/risk.js'"
  SOLUTION: The import path is wrong or the file doesn't exist.
            Check that risk.js exists at: src/riskManagement/risk.js

  PROBLEM: Bot is scanning but never finding patterns
  SOLUTION: This is NORMAL — H&S patterns are rare. The bot may scan for
            days or weeks before finding a valid setup. This is by design.
            You can verify it's working by checking:
            http://localhost:3001/status → shows "online"
            Also check: the BarsToRequest in MT5 EA should be 250.

  PROBLEM: Trades are not being executed even when a signal appears
  SOLUTION: Check:
            1. Is AutoTrading enabled in MT5?
            2. Is the EA face yellow on the chart?
            3. Is the balance being sent? Look for "Balance: $X" in server logs.
            4. Is canTrade() returning true? Check closedTrades.json trade count.
            5. Is it within trading hours?

  PROBLEM: PM2 shows "errored" status
  SOLUTION: Run `pm2 logs` to see the error message.
            Common cause: port 3001 is already in use. Run `pm2 delete all`
            and try `pm2 start pm2.ecosystem.config.cjs` again.

  PROBLEM: Dashboard shows $0 balance
  SOLUTION: The balance is only updated when MT5 polls /execute.
            If MT5 is not connected, balance will show 0. This is expected.

  12. HOW TRADES ARE CALCULATED
================================================================================

  STOP LOSS PLACEMENT:
  ────────────────────
  For a Head & Shoulders (SELL):
    SL = Right Shoulder High + 0.0005 (0.5 pip buffer above the shoulder)
    For JPY pairs: SL = Right Shoulder High + 0.05 (5 pip buffer)

  For an Inverted H&S (BUY):
    SL = Right Shoulder Low − 0.0005 (0.5 pip buffer below the shoulder)
    For JPY pairs: SL = Right Shoulder Low − 0.05

  TAKE PROFIT (TP) PLACEMENT — HISTORICAL S/R ZONES:
  ──────────────────────────────────────────────────────
  The TP is NOT just a random 1:3 formula. The bot scans past price history 
  for key Support & Resistance zones:

  1. For a SELL (Head & Shoulders):
     - Scans past candles for historical swing Lows (Support zones) below entry.
     - Identifies the nearest key Support zone in the path of the trade.
     - Snaps the initial TP target directly to that key Support zone!

  2. For a BUY (Inverted H&S):
     - Scans past candles for historical swing Highs (Resistance zones) above entry.
     - Identifies the nearest key Resistance zone in the path of the trade.
     - Snaps the initial TP target directly to that key Resistance zone!

  3. RR CAPPING & REJECTION RULES:
     Once the TP is snapped to the historical Support/Resistance zone, the bot 
     calculates the Risk:Reward (RR = TP distance ÷ SL distance):

     - IF RR > 3.0: 
       The key zone is far away. The bot CAPS the TP at exactly 3.0 RR so it 
       does not greedily target unreasonable targets.

     - IF RR < 2.5: 
       A key Support or Resistance level is blocking the path before 2.5 RR 
       can be achieved. The trade is REJECTED (NO TRADE) because taking it 
       would mean risking money against a blocking historical level.

     - IF 2.5 <= RR <= 3.0: 
       PERFECT TRADE! TP is placed directly at the historical Support/Resistance 
       level.

  LOT SIZE CALCULATION:
  ─────────────────────
  Example: Account Balance = $1,000, Risk = 5%, EURUSD, SL = 15 pips

    Risk Amount = $1,000 × 5% = $50
    SL in pips  = 15 pips
    Pip value   = $10 per lot per pip (for EURUSD)
    Lot Size    = $50 ÷ (15 × $10) = $50 ÷ $150 = 0.33 lots

  The bot automatically adjusts:
  - As your account grows → lot sizes grow
  - As your account shrinks → lot sizes shrink
  - Minimum lot size: 0.01 (micro lot)

  13. DEPLOYING TO A VPS — COMPLETE SETUP GUIDE
      (Do You Need VS Code? What to Install? Will Ports Be the Same?)
================================================================================

  DO YOU NEED VS CODE ON THE VPS?
  ─────────────────────────────────
  NO. VS Code is a code editor — it is for writing and editing code on your
  own computer. On a VPS you are only RUNNING the bot, not editing it.
  Everything on a VPS is done through a terminal (command line only). No
  graphical apps needed.

  ════════════════════════════════════════════════════════════════════════════
  THE MOST IMPORTANT DECISION: WINDOWS VPS vs LINUX VPS
  ════════════════════════════════════════════════════════════════════════════

  Before setting anything up, decide which type of VPS you are getting.
  This determines whether the ports need to change.

  ────────────────────────────────────────────────────────────────────────────
  OPTION A — WINDOWS VPS  (Recommended for beginners)
  MT5 and Node.js both run on the SAME Windows VPS
  ────────────────────────────────────────────────────────────────────────────

  Architecture:
    [Your Windows VPS]
       ├── MetaTrader 5     (runs the EA, makes trades)
       ├── Node.js server   (port 3001)  ← MT5 calls 127.0.0.1:3001
       └── Next.js dashboard(port 3000)  ← you open in browser via VPS IP

  Port situation: PORTS STAY EXACTLY THE SAME as your local setup.
    127.0.0.1:3001 works because MT5 and the server are on the same machine.
    No firewall changes, no code changes, nothing to update.

  Pros:
    ✅ Everything is the same as running locally — no configuration changes
    ✅ You access MT5 via Remote Desktop (just like sitting at the computer)
    ✅ Simplest mental model — one machine does everything
    ✅ You can close your RDP session and everything keeps running

  Cons:
    ❌ Windows VPS costs more — typically $15–$25/month
    ❌ Slightly higher RAM usage (Windows overhead)

  What you need installed on a Windows VPS:
    - Node.js v20     → download from https://nodejs.org (Windows installer)
    - Git             → download from https://git-scm.com (Windows installer)
    - PM2             → installed via terminal: npm install -g pm2
    - MetaTrader 5    → download from your broker's website
    - That is all. No VS Code. No anything else.

  ────────────────────────────────────────────────────────────────────────────
  OPTION B — LINUX VPS  (Cheaper, more common)
  Node.js runs on the VPS. MT5 stays on your LOCAL Windows PC.
  ────────────────────────────────────────────────────────────────────────────

  Architecture:
    [Your Local Windows PC]           [Linux VPS]
       └── MetaTrader 5  ──────────►  Node.js server (port 3001)
             (EA must point                └── Dashboard  (port 3000)
              to VPS IP address)

  Port situation: THE EA URLS MUST CHANGE.
    Because MT5 and the server are on different machines, 127.0.0.1 no longer
    works. 127.0.0.1 means "this machine". You must point the EA at the
    VPS's public IP address instead.

  The ONE code change required in MT5_TradeExecutor.mq5 (lines 13–14):

    BEFORE (works locally):
      input string ExecuteURL = "http://127.0.0.1:3001/execute";
      input string CandlesURL = "http://127.0.0.1:3001/candles";

    AFTER (Linux VPS — replace with your actual VPS IP):
      input string ExecuteURL = "http://YOUR.VPS.IP.HERE:3001/execute";
      input string CandlesURL = "http://YOUR.VPS.IP.HERE:3001/candles";

  NOTE: You do NOT need to edit the file to do this. When you attach the EA
  to a chart in MT5, go to the Inputs tab and change the URLs there directly.
  That is simpler and does not require recompiling.

  You also need to open port 3001 on the VPS firewall (see setup steps below).

  Pros:
    ✅ Cheaper — typically $5–$10/month
    ✅ Linux is stable and fast for running Node.js servers
    ✅ More common for server deployments

  Cons:
    ❌ MT5 stays on your local PC — your PC must be ON when you want to trade
    ❌ You must update the EA URLs
    ❌ Port 3001 must be opened in the firewall

  What you need installed on a Linux VPS:
    - Node.js v20   (installed via terminal command — see steps below)
    - Git           (installed via terminal — usually pre-installed)
    - PM2           (installed via terminal: npm install -g pm2)
    - That is all. No VS Code. No MetaTrader. No GUI apps of any kind.

  ════════════════════════════════════════════════════════════════════════════
  REFERENCE TABLE — What Changes Between Local, Windows VPS, Linux VPS
  ════════════════════════════════════════════════════════════════════════════

    Item                  | Local (now)        | Windows VPS        | Linux VPS

  ════════════════════════════════════════════════════════════════════════════
  FULL STEP-BY-STEP: WINDOWS VPS SETUP
  ════════════════════════════════════════════════════════════════════════════

  HOW GITHUB WORKS WITH YOUR VPS (ONE-WAY ONLY):
  ──────────────────────────────────────────────────
  You NEVER push code *from* your VPS. The flow is strictly one-way:

  1. On your LOCAL PC (where code is stored): You PUSH your code up to GitHub.
  2. On your WINDOWS VPS (where the bot runs): You only CLONE (download) the code down from GitHub.

  Once downloaded onto the VPS, you don't touch GitHub on the VPS again.
  The VPS will run MT5 + Node.js 24/7 completely independently, even when 
  your local computer is powered off.

  (Alternative: If you don't want to use GitHub at all, you can simply Copy/Paste
   the project folder directly from your PC onto the Windows VPS desktop screen
   over Remote Desktop!)

  STEP 1 — Log into the VPS via Remote Desktop
    Open "Remote Desktop Connection" on your Windows PC (search in Start menu)
    Enter your VPS IP address
    Enter the username and password your VPS provider gave you
    → A Windows desktop will appear — this IS the VPS

  STEP 2 — Install Node.js on the VPS
    Open a browser on the VPS, go to https://nodejs.org
    Download and install the LTS version (same as installing on your own PC)
    Verify: open Command Prompt, type: node --version
    You should see: v20.x.x or higher

  STEP 3 — Install Git on the VPS
    Go to https://git-scm.com, download and install Git for Windows
    Verify: git --version

  STEP 4 — Clone the project from GitHub
    Open Command Prompt on the VPS:
    git clone https://github.com/YOUR_USERNAME/HS-UI.bot.git
    cd HS-UI.bot

  STEP 5 — Install dependencies and build the dashboard
    npm install
    npm run build
    (build takes 1–3 minutes, only needed once or after UI changes)

  STEP 6 — Install PM2 and start the bot
    npm install -g pm2
    npm run start:prod

  STEP 7 — Verify both processes are running
    pm2 status
    You should see hs-bot-server (online) and hs-dashboard (online)

  STEP 8 — Make PM2 survive a VPS reboot (IMPORTANT)
    pm2 startup
    Copy the command it prints and run it (it will look like:
    pm2 startup powershell -u Administrator --hp C:\Users\Administrator)
    pm2 save

  STEP 9 — Install MetaTrader 5 on the VPS
    Download from your broker's website and install normally
    Follow Section 6 of this guide exactly — all steps are the same
    The EA URLs stay as http://127.0.0.1:3001 — do not change them

  STEP 10 — Close Remote Desktop
    You can now close the RDP window. Everything keeps running on the VPS.
    MT5 will continue running in the background as long as the VPS is on.

  STEP 11 — Verify the bot is working from your browser
    Open http://YOUR_VPS_IP:3000 in your browser
    You should see the dashboard
    Also check: http://YOUR_VPS_IP:3001/status

  ════════════════════════════════════════════════════════════════════════════
  FULL STEP-BY-STEP: LINUX VPS SETUP
  ════════════════════════════════════════════════════════════════════════════

  BEFORE YOU START: Push your code to GitHub from your local PC (see above).

  STEP 1 — Connect to the VPS via SSH
    On Windows, open PowerShell or download PuTTY (https://putty.org)
    Type: ssh root@YOUR_VPS_IP
    Enter your VPS password when prompted
    → You are now inside the VPS terminal

  STEP 2 — Install Node.js v20
    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
    sudo apt-get install -y nodejs
    Verify: node --version  (should show v20.x.x)

  STEP 3 — Install Git (if not already present)
    sudo apt-get install -y git
    Verify: git --version

  STEP 4 — Install PM2
    npm install -g pm2
    Verify: pm2 --version

  STEP 5 — Clone the project from GitHub
    git clone https://github.com/YOUR_USERNAME/HS-UI.bot.git
    cd HS-UI.bot

  STEP 6 — Install dependencies
    npm install

  STEP 7 — Build the Next.js dashboard
    npm run build
    (This compiles the dashboard for production. Takes 1–3 minutes.)

  STEP 8 — Open the firewall ports
    sudo ufw allow 3000    ← dashboard (you access this in browser)
    sudo ufw allow 3001    ← bot server (MT5 sends data here from your PC)
    sudo ufw allow 22      ← SSH (keep this open or you lose access!)
    sudo ufw enable
    sudo ufw status        ← verify the ports are listed as ALLOW

  STEP 9 — Start both processes with PM2
    npm run start:prod
    pm2 status             ← both should show "online"

  STEP 10 — Survive reboots
    pm2 startup
    (Copy the full command it prints and run it. It looks like:
     sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u root --hp /root)
    pm2 save

  STEP 11 — Update MT5 EA on your LOCAL PC (the URL change)
    In MetaTrader 5 on your local machine:
    - Double-click the EA on the chart (or drag it from Navigator again)
    - Go to the "Inputs" tab
    - Change ExecuteURL to: http://YOUR_VPS_IP:3001/execute
    - Change CandlesURL to: http://YOUR_VPS_IP:3001/candles
    - Click OK

    NOTE: You also need to add this URL to MT5's allowed list:
    Tools → Options → Expert Advisors → Allow WebRequest for listed URL
    Add: http://YOUR_VPS_IP:3001

  STEP 12 — Verify everything is connected
    On your LOCAL PC, check the MT5 Experts tab.
    You should see scan responses appearing every 5 minutes:
    "📤 [EURUSD] Scan response: {"status":"scanning"}"

    From your browser, open:
    http://YOUR_VPS_IP:3000  → dashboard
    http://YOUR_VPS_IP:3001/status  → health check
